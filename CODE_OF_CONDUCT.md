# Code of Conduct

## The standard

Be straight with people and assume they are doing the same. Disagreement about technical
substance is welcome and expected. This project starts from the position that being careful
is not a strategy. Contempt for the person on the other side of the argument is not.

Concretely, in this project:

- **Criticise the design, not the designer.** "This check can't fail, here's a case that
  proves it" is the whole point. "Whoever wrote this doesn't understand testing" is not.
- **Say what you actually verified.** If you ran it, say what happened. If you reasoned about
  it without running it, say that instead. Overstating what you checked wastes reviewer time
  in a way that is hard to detect and expensive to unwind.
- **Take a correction plainly.** Being wrong about something is ordinary here, several of
  this repo's devices exist because a maintainer's own check turned out to be measuring
  nothing. Fix it, note what the fix prevents next time, move on.
- **Do not use someone's inexperience against them.** A question that seems obvious to you is
  a question the docs failed to answer.

Unacceptable: harassment, personal or demographic attacks, sustained disruption, publishing
someone's private information, or sexualised attention of any kind.

## Scope

Applies in issues, pull requests, discussions, commit messages and code comments, and
anywhere someone is representing this project publicly.

## Reporting

Report to **rainmanjam@gmail.com**. Reports stay confidential, and you will get a response
within a week. If your report concerns the maintainer, say so: an unsatisfactory answer to
that is a legitimate reason to escalate publicly.

Maintainers may edit or remove contributions that violate this document, and may block
accounts for repeated or severe violations. Where the call is a judgement one, the reasoning
gets stated rather than being left implicit.
