CLAUDE.md text isn't an enforcement mechanism — it's part of the prompt context. Every instruction in there, no matter how many times you repeat it or how loud the caps are, is just another signal competing with everything else in the context window (the current task, other instructions, tool outputs). At any given step there's some nonzero probability the model doesn't weight that instruction highly enough, especially in long sessions where earlier context gets diluted or summarized. Repetition and caps nudge the odds but can't get you to zero — you're fighting a probabilistic system with a probabilistic lever.

The two things you listed are exactly the case where that's the wrong tool. "Never edit `src/generated/`" and "never force push" are both mechanically checkable — you don't need judgment to detect them, just a match on the file path or the git command. That means you can enforce them deterministically with a **PreToolUse hook** in `.claude/settings.json`: a shell script that runs before every `Edit`/`Write`/`Bash` call, inspects the proposed action, and exits non-zero (blocking it) if it touches `src/generated/` or contains `git push --force`/`-f`. That runs outside the model entirely — no amount of the model "forgetting" can bypass it, because it never gets a vote.

Rule of thumb: put the instruction in CLAUDE.md if it requires judgment ("prefer composition over inheritance"); put it in a hook if it's a hard mechanical boundary ("never touch this path," "never run this exact command").
