Nothing is wrong with your wording — you're using the wrong *kind* of control. CLAUDE.md is advice to the model; it gets read once, competes with everything else in context, and degrades exactly when you need it most (long sessions, post-compaction, subagents that never saw your file, "the user seems to want this done" pressure). Caps and repetition buy maybe a percentage point. A 10% failure rate is about what a prose-only guard looks like.

In poka-yoke terms: you've built an instruction, not a fixture. Move both rules down to the layer that executes the action rather than the layer that decides to.

**Force push — make it mechanically impossible**

1. Harness deny rule (`.claude/settings.json`):
   ```json
   "permissions": { "deny": ["Bash(git push --force*)", "Bash(git push -f*)", "Bash(git push *--force*)"] }
   ```
   Claude never gets to run it, regardless of what it believes.
2. Server-side backstop: GitHub branch protection "Allow force pushes" off on `main` (and any long-lived branches). This catches the case where Claude rewrites the command (`git push origin +main`) or a subagent runs with different settings. The server doesn't care how convinced the model was.
3. Optional: a `PreToolUse` hook that greps the command for `--force`, `-f`, or `+refs` so you get a clear message instead of a silent deny.

**src/generated/ — deny writes, and make it self-healing**

1. Deny rule: `"Edit(src/generated/**)"`, `"Write(src/generated/**)"`, plus `"Bash(* src/generated/*)"` if you want belt-and-suspenders (sed/echo redirects bypass Edit).
2. A `// @generated — DO NOT EDIT, run `npm run codegen`` header at the top of each file — the tool sees this *at the moment of editing*, which is the only place a reminder actually helps.
3. CI check: re-run codegen and `git diff --exit-code src/generated/`. If a hand-edit slips through, it can't merge. This is the real guarantee; the deny rule just saves you the round-trip.

**Then strip the rules out of CLAUDE.md** (or reduce to one sentence pointing at the mechanism: "src/generated is regenerated by `npm run codegen`; edit the schema instead"). Every shouted rule dilutes the rest of the file, and a rule that's enforced elsewhere doesn't need to be shouted.

If yes, the deny pattern must not match it and branch protection only covers `main`. If no, block all force variants everywhere.
