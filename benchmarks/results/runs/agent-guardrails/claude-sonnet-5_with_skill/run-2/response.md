Using poka-yoke's `agent-guardrails` mode: instructions in CLAUDE.md are rung-zero. They only work if something reads and applies them before every tool call — and things that reliably skip that read are exactly what a 1-in-10 failure rate points to: context compaction dropping the file, a subagent spawned without your CLAUDE.md in its prompt, or the model just pattern-matching "this looks fine" under load. Writing it in caps, twice, doesn't change that — it's still text the agent has to *remember*, not a mechanism that stops the call.

The fix is a device that runs before the tool executes, not more text. That's five pieces, not one:

**1. Deny rules — the actual syntax, not a description of one.** In `.claude/settings.json` (committed, not `.local.json` — a local-only rule protects one machine):
```jsonc
{
  "permissions": {
    "deny": [
      "Bash(git push --force:*)",
      "Bash(git push -f:*)",
      "Edit(./src/generated/**)",
      "Write(./src/generated/**)"
    ]
  }
}
```

**2. A hook for what a pattern can't catch.** `Bash(git push --force:*)` only matches if `--force` is literally the prefix — it misses `-f`, `--force-with-lease` abuse, or `git push origin +main`. And nothing stops an agent from overwriting `src/generated/` via `Bash(cat > src/generated/x.ts)` — deny rules on `Edit`/`Write` don't cover Bash writes. This repo already has exactly that hook, unused: `plugins/poka-yoke/assets/devices/claude-hooks/guard_dangerous_commands.py` regexes force-push variants (keeping `--force-with-lease` allowed) and denies protected paths. It doesn't yet know about `src/generated/` — that's a path-regex addition, not new logic.

**3. The deny message.** A bare "denied" makes an agent route around it. The existing script's pattern is right: name what was blocked, why, and the alternative — e.g. *"src/generated/ is regenerated by \[codegen command]; edit the source template instead and regenerate."*

**4. Where it lives.** `.claude/settings.json` + `.claude/hooks/guard_dangerous_commands.py`, both committed. Right now this repo has no `settings.json` and no `.claude/hooks/` — so today literally nothing enforces either rule; the 1-in-10 "works" is only ever CLAUDE.md getting read and obeyed by chance.

**5. Proof it fires.** Before trusting it: run `git push --force origin main` and confirm the deny + message, run a plain `git push` and confirm it's unaffected, same pair for an edit inside vs. outside `src/generated/`.
