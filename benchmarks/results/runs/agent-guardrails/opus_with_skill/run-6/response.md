## What you're doing wrong

Nothing about the *wording*. Caps, repetition, emphasis — none of it changes the mechanism. Instructions to an agent are rung zero on Shingo's ladder: they're training, and training degrades. Under a long context, after compaction, or in a subagent that never read your CLAUDE.md, the rule simply isn't present. One-in-ten is exactly the hit rate a rung-zero control produces. Writing it a third time in caps gets you one-in-ten again.

Your two rules also need *different* devices, which is why one fix won't cover both.

`★ Insight ─────────────────────────────────────`
A deny rule matches the **start** of the command string. That makes it perfect for a path glob and unreliable for a flag that can move — which is precisely the split between your two rules.
`─────────────────────────────────────────────────`

## 1–2. The devices

`src/generated/` is a path, so a deny rule is enough. Force-push is a flag with escape hatches (`-f`, `git push origin --force`, `git push origin +main`), so it needs a hook that inspects the whole command.

```jsonc
// .claude/settings.json
{
  "permissions": {
    "deny": [
      // poka-yoke: generated files are rewritten by codegen; edits here vanish silently
      "Edit(./src/generated/**)",
      "Write(./src/generated/**)",
      "MultiEdit(./src/generated/**)"
    ]
  },
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "python3 \"${CLAUDE_PROJECT_DIR}\"/.claude/hooks/guard_dangerous_commands.py"
      }]
    }]
  }
}
```

The bundled `guard_dangerous_commands.py` already carries the force-push rule with the `--force-with-lease` lookahead, so the safe form stays allowed.

## 3. The deny message is the device

A bare "denied" makes the agent invent a workaround — often worse. The message must name what was blocked, why, and the alternative:

> Blocked: edit to `src/generated/`. These files are regenerated by codegen, so your change is overwritten on the next build and disappears without an error. Edit the schema/template it's generated from, then re-run codegen.

## 4. Where it lives

`.claude/settings.json`, **committed**. In `settings.local.json` it protects one machine — the same failure mode as documenting it.

## 5. Prove it fires

Untested hooks fail open while looking like protection:

```bash
echo '{"tool_name":"Bash","tool_input":{"command":"git push -f origin main"}}' \
  | python3 .claude/hooks/guard_dangerous_commands.py   # expect: deny
echo '{"tool_name":"Bash","tool_input":{"command":"git push --force-with-lease"}}' \
  | python3 .claude/hooks/guard_dangerous_commands.py   # expect: no output
```

Then delete both lines from CLAUDE.md. Leaving them creates the impression the rule is enforced twice when it's now enforced once.
