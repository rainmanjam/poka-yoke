## Goal Description
The problem is that you are relying on *instructions* (training) rather than *devices* (poka-yokes) to prevent unwanted behaviors (editing generated files and force pushing). 

As the core philosophy of this repository states: **"If your change relies on someone remembering something, it is not finished."** AI agents, like humans, suffer from context degradation and probabilistic adherence to prose. Shouting in all-caps just competes for a truncated attention budget. 

To fix this, we need to replace the instructions with devices that physically or systematically prevent the error from occurring. A device doesn't require the agent to remember anything; it just catches the failure silently or fails loudly when violated.

## Proposed Changes

We will introduce two classes of devices to physically prevent these actions.

### 1. Device for `src/generated/`

Instead of telling the agent not to touch the files, we remove its ability to do so, or make it immediately obvious if it tries.

#### [NEW] Read-only File Permissions
Modify your generation script to strip write permissions from the generated files immediately after creating them. 
```bash
# In your generator script:
chmod a-w src/generated/*
```
If an agent or human tries to edit the file directly, the editor or OS will block it, forcing them to realize they are doing something wrong.

#### [NEW] Pre-commit Hook for Generated Files
Add a device that fails the commit if generated files are modified manually.
```bash
# .git/hooks/pre-commit
# Checks if src/generated files are staged, and if so, ensures they were generated by the script
# (e.g., by checking a checksum or simply blocking direct edits).
```

### 2. Device for Force Pushing

Force pushing is a Git operation that cannot be prevented by markdown instructions.

#### [NEW] Branch Protection Rules (GitHub/GitLab)
Configure the repository settings on your remote host to disable force pushes to protected branches (like `main` or `master`). This is the ultimate device, as it enforces the rule at the server level.

#### [NEW] Git Pre-push Hook
For local enforcement, we can add a git hook that intercepts and blocks force pushes.
```bash
# .git/hooks/pre-push
#!/bin/bash
if grep -q "force\|+refs" <<< "$@"; then
    echo "ERROR: Force push detected and blocked by poka-yoke device."
    exit 1
fi
```
