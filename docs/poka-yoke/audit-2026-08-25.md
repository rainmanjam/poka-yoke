# Poka-Yoke Audit — work since v0.1.2 — 2026-08-25

**Scope**: `v0.1.2..HEAD`, 17 files, 554 insertions. Substantially the vendored-copy drift
device, the plugin-scanner CI gate, and the generated logo references.

**Verdict**: The drift device can be disarmed by deleting its own input and CI stays green.
Emptying `copies` in `vendored.lock.json` produces "nothing to check" and exit 0 — the same
absent-data-does-not-raise shape this repository exists to catch, inside the device built to
prevent a vendored copy from rotting.

Every finding below was reproduced, not inferred.

## Findings

### 1. The drift check disarms itself when its input is emptied — silent data drift / trivial

**Where**: `scripts/vendored_copies.py:186` (`cmd_check`)

**Mistake**: Delete an entry from `vendored.lock.json`, or empty `copies`, while tidying up.

**Consequence**: `--check` prints `no vendored copies recorded; nothing to check` and exits 0.
CI is green. The copy at `sickn33/agentic-awesome-skills` (45k stars) then ages silently,
which is the exact outcome the device was built to prevent. Reproduced: emptying `copies`
gives exit 0.

**Today**: **None.** The empty case is treated as "nothing to do" rather than "something is
missing".

**Device**: A test that asserts the lock is non-empty and that every recorded `source_path`
exists. The lock is committed state, so its emptiness is a fact CI can assert.

```python
def test_vendored_lock_is_not_empty(self):
    """Emptying the lock is how this device gets switched off without anyone deciding to."""
    reg = json.loads((REPO / "vendored.lock.json").read_text())
    self.assertTrue(reg["copies"], "vendored.lock.json has no copies; if a copy was "
                                   "genuinely withdrawn, delete this test in the same PR")
```

→ **Control.** The removal now has to be argued for in a diff rather than happening quietly.

### 2. `--update` never re-records the downstream hash — silent wrong output / requires only forgetting

**Where**: `scripts/vendored_copies.py:236` (`cmd_update`)

**Mistake**: Refresh the downstream copy, merge it, then run `--update` as the script's own
output instructs.

**Consequence**: `cmd_update` rewrites `source_sha256` only. `downstream_sha256` is read in
two places and written in none, so after a legitimate refresh `--online` reports
"`sickn33/agentic-awesome-skills` has edited their copy" **forever**. A check that cries wolf
gets switched off, which this file's own docstring says in as many words.

**Today**: **None.**

**Device**: `--update` should fetch the downstream copy and re-record both hashes together,
refusing when the fetch fails rather than writing a half-updated lock.

→ **Control.**

### 3. A manifest can reference a logo that does not exist — wrong output the user acts on / silent

**Where**: `scripts/sync_platform_manifests.py:33-34`, `plugins/poka-yoke/assets/brand/`

**Mistake**: Delete, rename, or move a brand asset.

**Consequence**: Reproduced — with `logo-512.png` deleted, `sync_platform_manifests.py
--check` exits 0, all 85 tests pass, the registry check passes, and the manifests keep
claiming `./assets/brand/logo-512.png`. The failure surfaces as a rejection from a
third-party reviewer. **This exact rejection already happened once**, from the OpenAI
uploader: `interface.logo is required and must reference a square image`.

**Today**: **None.**

**Device**: Assert in `tests/` that every image path any generated manifest names resolves
inside the plugin and is square.

```python
for key, rel in logo_refs(manifest):
    p = PLUGIN / rel.lstrip("./")
    self.assertTrue(p.is_file(), f"{key} names {rel}, which is not in the plugin")
    w, h = Image.open(p).size
    self.assertEqual(w, h, f"{key} is {w}x{h}; both marketplaces require square")
```

→ **Control.** Costs a Pillow import in tests; a stdlib PNG header read would avoid it
(bytes 16-24 of the IHDR chunk) at the price of being less obvious.

### 4. Flipping `downstream_state` to `live` is a manual edit — silent wrong output / requires only forgetting

**Where**: `vendored.lock.json` (`downstream_state`), `scripts/vendored_copies.py:190`

**Mistake**: The downstream PR merges; nobody hand-edits the JSON.

**Consequence**: `--online` keeps reporting "not merged downstream yet, nothing to compare"
and exits 0, so the downstream half of the device never actually runs. Partially mitigated:
`--online` now detects a landed copy and says the lock is stale — but only when somebody runs
`--online`, and the flip itself is still a hand edit.

**Today**: **Warning** (the detection added in #8).

**Device**: Have `--update` flip the state as part of re-recording both hashes, so the
transition is a side effect of the command the script already tells you to run.

→ **Control** for the flip. Note the residual: `--online` is not in CI, so nothing runs it on
a schedule. A weekly cron calling `--online` would close that, at the cost of a job that
fails when a third party is unreachable.

### 5. `safe_source_path` rejects any dot-directory — crash / needs an unusual but reachable input

**Where**: `scripts/vendored_copies.py:57` (`SEGMENT`)

**Mistake**: Vendor a file whose path contains a dot-directory —
`plugins/poka-yoke/.claude-plugin/plugin.json`, `.github/workflows/x.yml`.

**Consequence**: Reproduced — `LockError: source_path segment '.claude-plugin' is not a plain
name`. The error is loud and accurate about what it rejected, but wrong about why: the path is
legitimate. Someone will read it as a bug in the lock rather than in the validator. Today's
only entry is unaffected.

**Today**: **Control**, but over-tight.

**Device**: Allow a leading dot while still refusing `.` and `..` exactly:
`re.fullmatch(r"(?!\.{1,2}$)\.?[A-Za-z0-9][A-Za-z0-9._-]*", segment)`.

→ **Control**, with the traversal guarantee unchanged. Worth a test asserting `..` is still
rejected, since loosening a security regex is exactly where a mistake would be invisible.

### 6. Unbounded read of a remote response — degraded experience / needs deliberate misuse

**Where**: `scripts/vendored_copies.py:138` (`fetch`)

**Mistake**: None available to a normal user. It needs `raw.githubusercontent.com` to serve
something enormous.

**Consequence**: `resp.read()` with no cap buys whatever the server sends into memory. Found
by this repository's own detector (`F7 Unbounded read`), which is a point in the detector's
favour.

**Today**: **None.**

**Device**: `resp.read(MAX_BYTES + 1)` and reject anything longer. A SKILL.md is tens of
kilobytes; a 1 MiB ceiling is generous.

→ **Control.**

## Set aside

- **Missing lock key raises a bare `KeyError` traceback** (`vendored_copies.py:171`). Loud and
  it exits 1, so the failure is not silent — only ugly. A schema check would fold into
  finding 1.
- **`_check_source` returns a digest that no caller uses** beyond an `is not None` test. A
  misleading signature, not a hazard.
- **A drifted source hides downstream problems**: `cmd_check` skips `_check_downstream` when
  the source check fails. Defensible fail-fast, worth a comment saying it is deliberate.
- **Transitive sdists in the scanner workflow still run setup scripts**. Already documented in
  the workflow with the reason `--only-binary :all:` cannot be used.

Style, naming and structure were not reviewed. Nothing here is a readability finding.
