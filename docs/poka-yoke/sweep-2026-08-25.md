**#1 — The detector's CI gate cannot fail.** The mistake: an agent or contributor lands code containing any hazard the detector exists to catch. The consequence: the CI step named "Detector runs clean on this repo" prints the findings and goes green anyway, because `main()` ends in a bare `return 0` — verified live with three planted high-severity findings and EXIT=0. Perfectly silent in the only place that matters, the merge gate; the step can only fail if the detector fails to *run*. Device: a `--fail-on <severity>` flag defaulting to non-zero exit when findings meet the threshold, plus a CI self-test that plants a hazard and asserts the step goes red — a check proven to fail, per this repo's own rule.

**#2 — The action-pin check is green from every direction.** The mistake: nothing — the environment does it for you. Any rate-limit 403 (24 unauthenticated lookups per run from shared runner IPs), DNS failure, or API outage makes every lookup fail, and the job titled "pinned actions are current and immutable" still prints `✓ 24 action reference(s), all pinned and current` with exit 0; the `GH_TOKEN` the workflow exports is never read. Meanwhile the `--offline` mode that every PR and every local run actually executes prints the same "and current" from a code path that skips every currency check. Fully silent — the false sentence is the one almost everyone sees. Device: count failed lookups and exit 2 if any occurred; read the token; make the offline summary claim only what it checked.

**#3 — One premature `--update` permanently disarms the vendored-drift check.** The mistake as an action: edit a vendored SKILL.md, then run `vendored_copies.py --update` before the downstream refresh PR merges — the warning telling you not to lives at line 347, printed *after* the lock is written at line 339. Consequence: both hashes are re-baselined against the stale state, and every subsequent `--check` verifies green over a copy that is genuinely stale — the single condition the script exists to detect, disarmed forever, with no error and no exit code. Device: refuse to re-baseline when the fetched downstream body still hashes to the recorded value while the local source changed, behind an explicit override flag.

**#4 — The preregistration lock does not cover the treatment's executable half.** The mistake: edit `detect_hazards.py`, `cli.py`, or `device_registry.py` after arms are registered — scripts the treatment's own SKILL.md files invoke by relative path. Consequence: `preregister_arms.py --check` globs only `*.md`, sees nothing, and prints `✓ all 3 arms unchanged (28 files)`; since neither control arm ships scripts, the uncovered surface is one-sided toward the treatment, which is exactly the bias a preregistration lock exists to preclude. Silent, and it undermines the repo's central empirical claim. Device: hash every file under each arm root and put a file-count floor in `cmd_check` so a narrowed glob cannot pass by finding nothing to disagree with.

**#5 — The recommended detector modes have no empty-input control.** The mistake: run `--diff`, `--staged`, or `--since <ref>` — the invocations the audit and retro skills document — on a docs-only commit, outside a repo, or with a ref git rejects. Consequence: `git()` maps every failure to an empty string, the unsupported-file filter leaves `scanned = 0`, and the tool exits 0 reporting a clean scan; the zero-scan control the comment claims is repo-wide is indented inside the `--paths` branch only. Silent — the user named a ref, git refused it, the tool said "clean". Device: raise on non-zero git exit, hoist the `scanned == 0 → exit 2` control above the branch so all four modes share it, and always emit `count` and `files_scanned` in the JSON.
